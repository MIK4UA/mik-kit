# MIK Kit — общий набор для сайтов и сервисов на своём коде

Создан 25.10.2026 (Ф2 ТЗ «Единая система стандартов»). Михаил выбрал способ подключения «а»: отдельный репозиторий, продукты берут его npm-зависимостью с версией, датчик Ф3 показывает отставших. Зачем: правка наверху (брендбук, заголовки, проверка языков) должна менять все продукты, а не переписываться в каждом. Михаил, 24.10.2026: «Иначе зачем мне стандарты, про которые постоянно надо напоминать?»

## Место
- Наследует: `core.md` §4 (Б1 айдентика, Б2 языки, Б3 безопасность, Б6 деплой), `wiki/site-standards.md §0.1`.
- Источник цвета и шрифта — только `wiki/brand-identity.md`; `brand/tokens.css` генерируется (`npm run tokens`), руками не правится.
- Реестр заготовок: `wiki/standard-library.md` строка «Сайт или сервис на своём коде — общий набор».

## Состояние 0.1.0 (25.10.2026)
- Токены из брендбука: 14 основ, 11 токенов светлой темы, 7 тёмной, шрифт, шкала 16→48, веса — сверено с таблицами брендбука один в один.
- Заголовки и CSP: объект для Node, include для nginx, живая проверка `check-headers`.
- Проверка языков: обобщена из mik4ua; на mik4ua даёт тот же результат, что его собственный скрипт (176 ключей × 3 языка, 15 файлов — чисто).
- Шаблон Coolify (`Dockerfile.static` + `nginx.conf`) — **сборкой не проверен** (на рабочей машине нет Docker); проверяется на первом продукте в Ф4.
- 8 тестов `npm test` — зелёные.

## Публикация
Репозиторий публичный — `github.com/MIK4UA/mik-kit` (решение Михаила 26.10.2026: секретов нет, Coolify скачивает набор при сборке без ключей). Поэтому здесь нет результатов проверок живых сайтов — они в ТЗ и журнале инстанса. В набор не класть ничего, кроме общего кода и публичных данных бренда.
